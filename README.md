# RECSGPS 注文システム

RECSGPS（リモート始動阻止装置／GPS装置）の受発注を管理する Web システムです。
発注企業が台数を指定して注文し、MIAMIホールディングス株式会社が単価入力・請求書発行・納品登録を行います。

スマートフォンでの利用を前提に設計しており、一覧表は狭い画面ではカード表示に切り替わります。

---

## 1. できること

### 発注する側（株式会社エンジン／株式会社ThreeEight など）

| 機能 | 画面 |
|---|---|
| 台数を指定して新規注文（納品先・ご担当者・納品希望日・備考も指定可） | `/orders/new` |
| 累計注文台数・納品台数（納品待ち台数を含む）・請求済金額の確認 | `/orders` |
| 最近の注文の確認（カードをタップで詳細へ） | `/orders` |
| 注文履歴の一覧と明細（状況での絞り込み・20件ごとのページ送り） | `/orders/history`、`/orders/[id]` |
| 納品履歴の確認（分納にも対応） | `/deliveries` |
| 自社宛の請求書PDFのダウンロード | 注文詳細・注文履歴から |
| 注文のキャンセル（状況が「受付済」で、納品登録がない注文のみ） | 注文詳細 |

他社の注文・納品・請求書は一切参照できません。

注文一覧のカードは注文の状況で色分けされます（受付済＝金、一部納品＝紫、納品完了＝緑、請求書発行済＝青、キャンセル＝灰）。

### 注文を受ける側（MIAMIホールディングス株式会社）

| 機能 | 画面 |
|---|---|
| 請求書未発行の件数と、対応中の受注の一覧 | `/admin` |
| **対応中の受注からその場で納品登録**（納品先が複数ある場合はモーダルで選択） | `/admin` |
| 発注元別の累計（注文件数／受注台数／納品台数／納品残） | `/admin` |
| 受注一覧（状況・発注元での絞り込み、20件ごとのページ送り） | `/admin/orders` |
| **単価の入力**（注文ごと。税込単価から消費税を逆算） | `/admin/orders/[id]` |
| **台数の変更**（台数行の「台数を変更」ボタンからモーダルで入力） | `/admin/orders/[id]` |
| **請求書PDFの発行**（`INV-年-連番` で採番） | `/admin/orders/[id]` |
| **納品登録・取消**（分納可。注文台数の超過は登録不可） | `/admin/orders/[id]` |
| 納品一覧（発注元での絞り込み） | `/admin/deliveries` |
| **発注アカウントの追加・編集・停止**、標準単価の設定 | `/admin/settings` |
| 請求元情報（住所・登録番号・振込先など）の設定、テストメールの送信 | `/admin/settings?tab=seller` |

ダッシュボードには運用上の警告も表示されます。データベースが未接続のとき、および請求元の住所が未入力のときに、それぞれ対処法つきの案内が出ます。

## 2. 初期アカウント

初回起動時に以下の3件が自動作成されます。パスワードは scrypt でハッシュ化して保存され、平文では保持しません。

| 区分 | ID | パスワード | 会社名 |
|---|---|---|---|
| 受注 | `info@miamiholdings.co.jp` | `miami0383` | MIAMIホールディングス株式会社 |
| 発注 | `engine` | `miami0383` | 株式会社エンジン |
| 発注 | `kcar` | `3333` | 株式会社ThreeEight |

発注アカウントの追加は `/admin/settings` から行います。ID・パスワード・会社名を入力すれば即座にログインできるようになります。

## 3. セットアップ（GitHub → Vercel）

### 3-1. リポジトリの用意

このフォルダの中身をそのまま GitHub リポジトリにアップロードしてください。

### 3-2. データベースの接続（必須）

注文履歴・納品履歴を保持するため Postgres が必要です。Vercel の Marketplace から Neon などの Postgres を追加すると、接続文字列の環境変数が自動で設定されます。

1. Vercel のプロジェクト → Storage → Create Database → Postgres（Neon）を選択
2. リージョンは **Singapore (Southeast)** を選ぶ（Neon に東京リージョンはなく、日本から最も近いため）
3. **Auth はオフ**にする。認証は `lib/auth.ts` に自前で実装済みのため不要
4. プランは Free で足りる（保存するのは JSONB 1行のみ）
5. 作成したデータベースをプロジェクトに接続

テーブルは初回アクセス時に自動作成されるため、SQLを流す作業は不要です。

#### 関数のリージョンについて

Vercel の関数は既定で `iad1`（ワシントンD.C.）で実行されます。DBがシンガポールにある状態でこれを放置すると、1リクエストごとに太平洋を何度も往復します。
更新処理は `BEGIN` → `SELECT ... FOR UPDATE` → `UPDATE` → `COMMIT` の4往復を行うため、体感で1秒近く遅くなります。

そのため `vercel.json` で関数の実行リージョンをDBと同じシンガポール（`sin1`）に固定しています。
DBのリージョンを変える場合は、この値も合わせて変更してください。

```json
{ "regions": ["sin1"] }
```

> **接続を忘れると注文データが消えます。**
> `POSTGRES_URL` / `DATABASE_URL` が未設定の場合、アプリは一時ディレクトリ（`/tmp`）にデータを保存します。
> 画面は動きますが、Vercel の関数が入れ替わるたびに注文・納品の記録が初期化されます。
> この状態のときは受注側ダッシュボードに警告が表示され、サーバーログにも次の警告が出ます。
>
> ```
> [recsgps] データを一時ディレクトリ (/tmp/recsgps-data) に保存しています。
> ```

### 3-3. 環境変数

Vercel の Project Settings → Environment Variables に設定します。

| 変数名 | 必須 | 内容 |
|---|---|---|
| `POSTGRES_URL` または `DATABASE_URL` | ○ | Postgres の接続文字列。Vercel の Postgres 統合を使えば自動で入ります |
| `AUTH_SECRET` | ○ | セッション署名用のランダム文字列（16文字以上。32文字以上を推奨）。未設定でも開発用の固定値で動きますが、本番では必ず設定してください |
| `RESEND_API_KEY` | — | 受注通知メールを使う場合のみ |
| `RESEND_FROM_EMAIL` | — | Resend でドメイン認証済みの送信元アドレス |
| `NOTIFY_EMAIL` | — | 受注通知の宛先。カンマ区切りで複数指定可。既定は `info@miamiholdings.co.jp` |

`AUTH_SECRET` は次のコマンドで生成できます。

```bash
openssl rand -base64 32
```

### 3-4. デプロイ後にすること

1. `info@miamiholdings.co.jp` でログイン
2. `/admin/settings?tab=seller` から**請求元情報**（住所・TEL・インボイス登録番号・振込先・支払期限）を入力
   → 未入力の項目は請求書PDFに印字されません
3. `/admin/settings` から各発注企業の**標準単価**を設定（任意）
4. 各発注企業にIDとパスワードを通知

## 4. メール通知について

新規注文が入ると、`NOTIFY_EMAIL`（既定は `info@miamiholdings.co.jp`）宛に日本語の受注通知メールが届きます。注文番号・発注元・台数・納品希望日・納品先などを本文に記載します（単価と金額は含みません）。

送信には Resend を使います。`RESEND_API_KEY` が未設定のあいだは何も送信せず、注文自体は通常どおり登録されます。メール送信に失敗した場合も注文は失われず、原因はサーバーログに記録されます。

`/admin/settings?tab=seller` の「システム情報」で現在の設定状況を確認でき、有効なときは**テストメールの送信**も試せます。送信に失敗した場合は Resend が返した原因（ドメイン未認証など）が画面に表示されます。

実装は `lib/mail.ts` にまとまっています。

## 5. 業務の流れ

```
発注企業                        MIAMIホールディングス
  │
  ├─ 台数を入力して注文 ──────→ 受注一覧に表示（状況：受付済）
  │                                │
  │                                ├─ 単価を入力（必要なら台数を変更）
  │                                ├─ 請求書を発行（状況：請求書発行済）
  │  ← 請求書PDFをダウンロード ────┤
  │                                │
  │                                ├─ 納品登録（分納可。ダッシュボードからも登録可）
  │  ← 納品履歴に反映 ─────────┤
  │                                └─ 全数納品で「納品完了」
  └─ 累計注文台数・納品台数を確認
```

### 単価の扱い

- 発注アカウントごとに**標準単価**を設定できます。設定済みの場合、その企業の注文画面に金額が表示され、請求書の発行時にその単価が自動で適用されます。
- 標準単価が未設定の場合、注文画面には「単価確定後にご案内します」と表示され、受注側が注文ごとに単価を入力します。
- 消費税は税込単価から逆算します（インボイス制度の税率別一括計算に対応）。

### 台数の変更

受注側は、受け付けた注文の台数を後から変更できます。受注詳細の台数行にある「台数を変更」ボタンからモーダルを開いて入力します。

- 納品済みの台数より少なくはできません。減らす場合は先に納品記録を取り消してください。
- 台数に応じて状況を付け直します。納品済みが台数に達すれば「納品完了」になり、台数を増やして下回れば元の状況に戻ります。
- 請求書の発行後に台数を変えると請求金額も変わります。モーダルにその旨を表示します。
- キャンセル済みの注文は変更できません。

## 6. 請求書PDFについて

`/admin/orders/[id]` の「請求書を発行する」で `INV-年-連番` を採番し、PDFを生成します。発注側も注文詳細・注文履歴から同じPDFをダウンロードできます。

レイアウトの要点は次のとおりです。

- 請求元ブロックは社印風の体裁で、会社名を大きく、その下に住所・TEL・登録番号などをラベル付きの2列で組みます。
- `public/logo.png` を置くと、会社名と住所の横にロゴを表示します。縦位置は会社名と住所のブロックに対して中央に揃い、画像の縦横比は元のまま保ちます。ファイルがなければロゴの列ごと省略します。
- 住所は市区町村（政令指定都市の行政区を含む）までを1行目に収めて改行します。
- 請求先のご担当者名には自動で「様」を付けます。入力側に敬称が付いている場合は二重に付けません。
- 金額は税込単価から消費税を逆算して表示します。

## 8. 技術構成

- Next.js 14（App Router）／ React 18 / TypeScript
- 画面はサーバーコンポーネント、更新処理は Server Actions（`app/actions.ts`）
- 請求書PDF：`@react-pdf/renderer` + Noto Sans JP（`public/fonts/` に同梱）。文字幅の実測に `fontkit` を使用
- 認証：scrypt によるパスワードハッシュ ＋ HMAC-SHA256 署名付き httpOnly Cookie（有効期限12時間）
- データ保存：Postgres（`recsgps_state` テーブルに JSONB 1行）。ローカルは JSON ファイル

### 主なファイル

| パス | 役割 |
|---|---|
| `lib/types.ts` | 型定義、製品名、税率、金額計算、状況の色分け |
| `lib/store.ts` | データ保存層（Postgres／ファイル）、既存データの移行、採番 |
| `lib/auth.ts` | セッション管理・アクセス制御 |
| `lib/invoice-pdf.tsx` | 請求書PDFのレイアウト |
| `lib/pdf-fonts.ts` | PDF用フォントの読み込み |
| `lib/queries.ts` | 累計・集計の算出 |
| `lib/mail.ts` | 受注通知メール（Resend） |
| `lib/filters.ts` | 一覧の絞り込み条件の解釈 |
| `app/actions.ts` | 注文・単価・台数・請求書・納品・アカウントの各処理 |
| `app/error.tsx` | エラー画面（エラーIDの表示） |
| `components/` | ヘッダー、絞り込み、ページ送り、状況バッジなどの共通部品 |

### フォントについて

Noto Sans JP（Regular／Bold）を `public/fonts/` に同梱しています。各約5MBあるため、Vercel の関数サイズ上限に引っかかる場合はサブセットフォントへの差し替えを検討してください。

フォントとロゴは `next.config.mjs` の `outputFileTracingIncludes` で請求書APIの関数に同梱しています。PDFのアセットを増やす場合はここに追記してください。

## 9. 困ったときは

### 「エラーが発生しました」と表示される

画面にエラーIDが出ます。Vercel の Logs でそのIDを検索すると、該当リクエストのスタックトレースが確認できます。

よくある原因は次の2つです。

| 症状 | 原因 | 対処 |
|---|---|---|
| ログイン後にエラー画面になる | `POSTGRES_URL` が未設定、または接続先が落ちている | Vercel の Storage でデータベースを接続し、環境変数を確認する |
| ログには `データベースに接続できません` と出る | 接続文字列が誤っている／DBが停止中 | 接続文字列を再発行してプロジェクトに再接続する |

データベースが一時的に落ちていた場合、復旧後は再デプロイなしで自動的につながります。

### 請求書PDFがダウンロードできない

`public/fonts/` の Noto Sans JP が関数に同梱されていない可能性があります。
`next.config.mjs` の `outputFileTracingIncludes` で同梱を指示しているため、通常は設定変更なしで動作します。
それでも失敗する場合はサーバーログの `invoice pdf render failed` を確認してください。

### 更新したのに画面が変わらない

Next.js のクライアント側キャッシュが原因のことがあります。更新処理のあとは変化する検索パラメータ（`?ok=...`）を付けて遷移しているため通常は起きませんが、発生した場合はページを再読み込みしてください。

## 10. 注意事項

- 請求書PDFに印字される請求元情報は `/admin/settings?tab=seller` の入力内容がそのまま使われます。初期状態では会社名以外が空欄です。
- 納品台数の合計が注文台数を超える登録はできません。
- 納品登録がある注文はキャンセルできません。また、納品済みの台数を下回る台数変更もできません。
- 注文番号（`RG-年-連番`）と請求書番号（`INV-年-連番`）は連番で採番します。注文を取り消しても番号は再利用されません。
